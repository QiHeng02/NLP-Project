# Fake News Detection Across Text Formats

**EE6405 Natural Language Processing: Final Capstone Group Project (NTU)**

> **Research question:** We compare traditional ML, deep learning, graph-based models,
> BERT-type models and an LLM to find which approach detects misinformation best, and whether
> that changes across **long articles** (ISOT), **short claims** (LIAR) and **social media posts**
> (COVID-19). We use explainability tools to check *why* each model labels something as fake.

📋 **Plan, timeline, roles and requirements:** see [`PROJECT_PLAN.md`](PROJECT_PLAN.md)

---

## Datasets

| Dataset | Format | Size | Labels | Split | Source |
|---|---|---|---|---|---|
| **ISOT Fake News** | Long news articles | ~45k articles (before cleaning) | real / fake | Our own 80/10/10 stratified split, made after removing duplicates | [Kaggle](https://www.kaggle.com/datasets/clmentbisaillon/fake-and-real-news-dataset) |
| **LIAR** | Short political claims | 12,836 statements | 6-level truthfulness, also mapped to binary | Official 10,269 / 1,284 / 1,283 | [Wang, 2017](https://aclanthology.org/P17-2067/) |
| **COVID-19 Fake News** (Constraint@AAAI-2021) | Social media posts | 10,700 posts | real / fake | Official 6,420 / 2,140 / 2,140 | [Patwa et al., 2021](https://arxiv.org/abs/2011.03327) |

**Label convention (all datasets):** `0 = real`, `1 = fake`.
LIAR binary mapping: `fake = {pants-fire, false, barely-true}`; the 6-class labels are kept in `label_6`.

**ISOT leakage fixes (important):** the raw ISOT data contains label shortcuts. The `subject`
column alone predicts the label, real articles carry a "(Reuters)" dateline, and duplicate
articles leak across naive splits. `scripts/prepare_data.py` removes all three. See
[`PROJECT_PLAN.md` §3](PROJECT_PLAN.md#3-datasets-and-preprocessing-decisions).

## Quick start

> Recommended: **Python 3.11** (best package compatibility for gensim, SHAP and PyTorch Geometric).

```bash
# 1. Create and activate a virtual environment (Windows)
py -3.11 -m venv .venv
.venv\Scripts\activate
#    macOS/Linux: python3.11 -m venv .venv && source .venv/bin/activate

# 2. Install PyTorch for your GPU first: https://pytorch.org/get-started/locally/
#    e.g. CUDA 12.4: pip install torch --index-url https://download.pytorch.org/whl/cu124

# 3. Install the rest
pip install -r requirements.txt

# 4. Get data: LIAR + COVID download automatically; ISOT needs one manual step (see data/README.md)
python -m scripts.prepare_data

# 5. Sanity check: TF-IDF + Logistic Regression on all datasets, plus the ISOT leakage check
python -m scripts.run_sanity_baseline --leakage --author "Your Name"
python -m scripts.collect_results

# 6. Unit tests
pytest -q
```

Run every command from the **repository root**; the `python -m scripts.<name>` form needs this.

## How to use the shared code

```python
from src.data.loaders import load_splits
from src.evaluation.metrics import compute_metrics, log_run

splits = load_splits("covid")                 # {"train": df, "val": df, "test": df}
X_train, y_train = splits["train"]["text"], splits["train"]["label"]

# ... train your model ...

m = compute_metrics(y_true, y_pred, y_score=prob_fake)       # binary
# m = compute_metrics(y_true, y_pred, task="multiclass")     # LIAR 6-class (label_6)
log_run(model="bilstm", dataset="covid", split="val", metrics=m,
        params={"lr": 1e-3, "hidden": 128}, runtime_s=412.5, author="Your Name")
```

- **Tune on `val`, report `test` only at the results freeze** (see plan).
- For a cross-dataset test, set `train_dataset="isot", dataset="liar"` in `log_run`.
- Use `python -m scripts.collect_results` to rebuild the comparison table.

## Team workflow

1. **Branch per task:** `git checkout -b feat/<area>-<name>`, e.g. `feat/bilstm-alex`.
2. **Never commit data or checkpoints.** `.gitignore` already excludes `data/` and `models/`.
3. **Commit your `results/runs/*.json` and figures.** One file per run means no merge conflicts.
4. **Open a pull request into `main`**; one other member reviews it. This also gives everyone
   visible evidence of their contributions for the reflection and peer evaluation.
5. `git pull` before starting work each day.
6. Log any AI assistance in [`docs/ai_usage_log.md`](docs/ai_usage_log.md) when you use it.
